## 2. FR-19 상세: 디스코드 포럼 스레드 연동

### 2.1 기본 구조

- **포럼 채널 1개** (`#마을-운영`) 사용
- 포럼 태그: `대기` / `승인` / `거절` / `보류` / `완료`
- 이벤트 1건 = **포럼 글 1개(= 스레드 1개)**
- 관리자는 **스레드에 댓글**로 처리
  - `승인`
  - `거절 <사유>`
  - `보류 <사유>`
- 보조 수단으로 **✅ / ❌ / ⏸ 버튼**을 함께 부착 (오타·인텐트 문제 완화)
- 봇은 **버튼 우선**, 버튼이 없으면 **댓글 첫 단어** 파싱

### 2.2 처리 흐름

```
이벤트 발생
  → 백엔드가 봇에 요청 (queue)
  → 봇이 포럼 글 생성 (제목/본문 템플릿)
  → 담당 역할 멘션
  → 관리자 댓글 "승인" 또는 버튼 클릭
  → 봇이 권한 확인 → DB 반영 (status 전환)
  → 스레드에 결과 댓글 + 태그 변경 + 잠금(archive)
  → 감사 로그 기록
```

### 2.3 상태 머신

```
pending ──승인──▶ approved ──▶ done
   │
   ├─거절──▶ denied ──▶ done
   └─보류──▶ held ──▶ (재판정 가능)
```

- `approved`/`denied` 이후의 결정은 **무시**하고 "이미 처리됨" 안내
- `held`는 다시 `승인`/`거절` 가능
- 모든 전환은 `request_id` 기준 1회만 반영 (멱등성)

### 2.4 스레드 제목 규칙

| 이벤트 | 제목 예시 |
| --- | --- |
| 신규 승인 | `[승인] 닉네임 (uuid8)` |
| 밴 요청 | `[밴] 닉네임 · 사유 요약` |
| 밴 해제 | `[해제] 닉네임` |
| 신고 | `[신고] 대상 닉네임 · 유형` |
| 장기 미접속 정리 | `[정리] 60일 미접속 3명` |
| 런처 오류 | `[오류] 닉네임 · 런처 vX.Y.Z` |

### 2.5 본문 템플릿 (예: 승인)

```
신청 시각 : 2026-11-10 14:20 KST
닉네임    : ○○○
UUID      : 8e99e23b-...
런처 버전 : 1.0.0
요청 ID   : REQ-20261110-001

처리 방법
- 이 스레드에 "승인" 또는 "거절 사유"를 댓글로 남겨주세요.
- 버튼(✅/❌/⏸)으로도 처리할 수 있습니다.
```

### 2.6 권한·보안

- 결정 권한: `마을관리` 역할 보유자만 (봇이 역할 검증)
- 봇 권한: 채널 보기, 메시지 보내기, 공개 스레드 생성, 스레드 내 메시지, 스레드 관리, 태그 관리, 임베드, 리액션
- 인텐트: `Guilds`, `GuildMessages`, **`MessageContent`** (댓글 파싱)
- 선택: `GuildVoiceStates` (음성 잠수 채널 판정 시)
- 모든 결정은 `audit_log`에 기록 (결정자, 시각, 스레드 링크, 원문)

### 2.7 예외 처리

| 상황 | 처리 |
| --- | --- |
| 봇 다운/디스코드 장애 | 요청 큐에 보관, 복구 시 재생성 (dedupe key) |
| 스레드 생성 실패 | 일반 채널에 대체 글 + 관리자 알림 |
| 대량 이벤트(정리 후보 100명) | 스레드 100개 대신 **요약 글 1개 + 명단** |
| 중복 결정 | 무시 + "이미 처리되었습니다" 안내 |
| 권한 없는 사용자 댓글 | 무시 또는 "권한 없음" 안내 |
| 아카이브된 스레드 | 읽기 전용, DB에서만 상태 확인 |
